This corrected family implements separate logical Contract/Profile roles, bootstrap lifecycle states, strategic DevelopmentPhases, conditional Objective-Bound Generation Input, deterministic Roadmap selection, minimal ProjectStatus, atomic cardinality-bound transitions, specific safe stops, and locator-based portability. Conditional generation input is not a new mandatory planning layer.

## 1. Purpose

This family turns the logical roles and relationships defined by STD-011 into a complete, copyable Target Project reference package.

STD-011 continues to define the conformance floor. This family supplies a recommended physical layout and reusable authoring structures; it does not make those paths normative identities.

## 3. Required Inputs

- Target identity and repository boundary;
- Human-authored or Human-Governance-approved Mission source decisions;
- capability decomposition and ordering decisions;
- Target approval, review, and state-transition authorities;
- protected areas, source scope, validation requirements, and execution permissions;
- evidence identities and provenance.

## 4. Authority Boundary

This family owns reusable structure only. Instantiated artifacts are Target-owned.

It does not:

- invent Target purpose, capability order, current state, evidence, or approval;
- approve a Mission, Roadmap, ProjectStatus, declaration set, or conformance claim;
- make a generated Roadmap authoritative before Target acceptance;
- authorize execution or mutation;
- make the recommended paths mandatory;
- replace TargetRepositoryResolution or the STD-011 conformance profile.

## 5. Instantiation Rules

1. Resolve all required placeholders from Target-owned sources.
2. Assign stable identities before relying on paths.
3. Keep exactly one current Mission, DevelopmentPhases, Roadmap, ProjectStatus, and Target Declaration Profile identity.
4. Preserve the STD-011 authority chain.
5. Keep the exact declaration-profile heading, category headings, headers, and table-only region unchanged.
6. Record derivation and acceptance as separate evidence.
7. Do not mark a produced artifact approved, canonical, conformant, certified, or operational unless the owning authority separately records that decision.
8. Safe-stop when a required value, authority, role, relationship, or evidence item is unresolved.

## 6. Completion Condition

A package instance is structurally complete when:

- every mandatory STD-011 role resolves to one stable Target-owned identity;
- every required placeholder is resolved;
- the declaration profile is mechanically consumable;
- DevelopmentPhases contains all twelve generation-grade fields per capability;
- Roadmap derivation and acceptance evidence are distinct;
- ProjectStatus records one active work unit or one authorized next action;
- evidence and operational records bind claims to subjects and revisions;
- the readiness checklist has no unresolved structural blocker.

Structural completion is not a conformance result or approval.
